# 双版本适配

从 BlackSlience-Reaper/ActLikeIt2 的 `92ba4de2e6bfd386605a056900da0e6f8db9bd0a`（0.2.2）构建两个实现，发行版本改为 0.2.3，最低游戏版本改为 0.107.1。清单作者保持原作者 ShuiMuNianHua；双版本适配基于 BlackSlience-Reaper 分支。

## 差异

| 原版变化 | 影响 | 处理 |
| --- | --- | --- |
| 0.107.1 没有 RunManager.FadeOut | 原源码旧目标有两处编译错误 | 旧版按原版 TestMode 判断调用 Transition.RoomFadeOut；新版调用 FadeOut；方法体分为整个文件受条件控制的分部实现 |
| 0.107.1 没有 NBestiary.AddEvents | 字符串 Harmony 目标仍会编译，但安装失败 | 新版 AddEvents 前追加自定义章节；旧版 CreateEntries 后追加，确保发现集已建立 |
| Mod 的单程序集字段变为程序集集合 | 实现藏在 lib/ 下后不再自动参加模型发现 | 新版调用 AssociateAssemblyWithMod；旧版在检测完成后把 Mod.assembly 改写为实现再初始化；原版要等全部模组加载完才首次扫描模组类型，读到的已是实现程序集，不需要桥接 |

模型、保存字段、补丁类与数值不分叉。覆写/补丁声明之外的差异不使用行内 `#if`。

## 构建与发行

```bash
dotnet build ActLikeIt2.csproj -c Release -p:CompatibilityTarget=0.107.1
dotnet build ActLikeIt2.csproj -c Release -p:CompatibilityTarget=0.111.0
python3 tools/build_dual.py --pck /绝对路径/ActLikeIt2.pck
```

`CompatibilityTarget` 默认 0.111.0，只接受 0.107.1 / 0.111.0。`GameRefsRoot` 根目录下必须有 `<目标>/game-refs`，默认 `~/sts2-mods/HextechRunes/versioned-dll-backups`，可用 `-p:GameRefsRoot=...` 或打包脚本 `--refs` 覆盖。禁用 MSBuild CandidateAssemblyFiles，避免从工程旁的旧 DLL 覆盖目标 HintPath。obj/bin 按目标与配置隔离。实现的便捷取用路径为 `build/variants/<目标>/ActLikeIt2.dll`。

加载器始终用 0.107.1 引用构建，程序集身份是 `ActLikeIt2.Loader`。构建脚本不推送、不发布、不部署游戏。PCK 资源未改，沿用 0.2.2 发行资源；导出版本不得高于 Godot 4.5.1。

```text
build/dual-release/ActLikeIt2/
├── ActLikeIt2.json
├── ActLikeIt2.dll                 # 加载器
├── ActLikeIt2.pck                 # 两目标共用
├── actlikeit2-variants.manifest
├── bundle-evidence.json
└── lib/
    ├── 0.107.1/{ActLikeIt2.dll, compat-target.txt}
    └── 0.111.0/{ActLikeIt2.dll, compat-target.txt}
```

选择“不高于宿主的最新变体”；未知宿主失败。清单校验目标、路径、SHA-256、文件名、标记及程序集内目标元数据。旧版的 Mod.assembly 会在 initializer 返回后被原版覆盖，因此必须等检测完成后再关联，不能提前初始化实现。

失败处理：程序集身份与目标元数据在加载前用 PE 元数据读取校验；加载后、关联前先完整枚举一次类型，前置缺失时在关联前失败，不把类型加载异常带进原版的全体模组类型扫描。原版会吞掉初始化器异常并仍把模组记为 Loaded，所以加载器失败时在检测事件里把本模组改为 Failed，依赖它的模组随后得到缺少依赖的报错，而不是带着缺失的实现继续加载。读不到发行版本号时按未知宿主失败（sts2 程序集版本在各发行版都是 0.1.0.0，不能代替）。

`tools/LoaderContractCheck` 对发行目录做 19 项离线检查（不调用初始化）：版本选择、未知宿主、非法目录/目标/哈希/文件名/标记、两个真实变体的加载前元数据校验、目标元数据或身份打错的程序集、清单为空/损坏/缺失、变体 DLL 缺失。`tools/build_dual.py` 组装后对两个版本的引用各跑一次，不通过就不生成发行目录；同时检查共享 PCK 不含 obj/bin/加载器等构建中间产物，并在 `bundle-evidence.json` 里记录包括未跟踪文件在内的源码脏状态。

## 验证

- 两个实现和稳定加载器零错误编译。非支持目标值会直接失败。
- 元数据清单：1 个模型、0 个 SavedProperty、20 个补丁类、23 个常量字段，两个目标完全一致；源码数值清单一致。证据位于 `snapshots/<目标>/`。
- 两目标静态 Harmony 目标及按名称注入参数均解析成功；1 个动态目标不由该静态检查证明。
- 加载器 19 项离线检查通过，不执行初始化；打包时对两个版本的引用各跑一次。
- 0.111.0 与 RitsuLib 0.6.2、LibraryOfRuinaLib 1.3.3、本体 0.22.7 在 APFS 克隆、隔离 HOME、`--headless --force-steam=off` 下加载。日志确认选择 0.111.0、官方关联成功、ActLikeIt2 初始化完成；实际补丁表覆盖 20/20 个类，共 25 个补丁方法记录。本体验证模组的双版本检查确认 ActLikeIt2 实现已关联到模组记录。另一次运行删掉基础库的 lib/：基础库加载器失败并标记为 Failed，本体按缺少依赖不加载，ActLikeIt2 照常加载。
- **0.107.1 未做运行时加载验证**。章节选择、图鉴展示、完整战斗、存档和双机联机未做运行验证。

离线审计由配套本体仓库的 `tools/DualTargetAudit`、`tools/compare_dual.py` 执行；它们读取本仓库发行包，不修改实现。加载器检查随本仓库 `tools/LoaderContractCheck` 提供。只提交 PR，未合并或上传工坊。
